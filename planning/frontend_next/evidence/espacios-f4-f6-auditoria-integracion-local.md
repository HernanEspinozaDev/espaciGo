## F4 — flujo y diferencias verificadas

- **UI:** `frontend/src/features/host-listings/ui/listing-editor.tsx` gestiona selección, previews, cola y estados. `use-host-listings.ts`, la facade/port y `host-listings-openapi-adapter.ts` conducen las operaciones hacia el BFF. La cobertura Playwright citada en `espacios-galeria-ui.md` usa `mockGateway`; no prueba el servicio real.
- **BFF:** `frontend/src/app/api/backend/[...path]/route.ts` limita operaciones, toma la sesión del cookie en el servidor y hace proxy al backend. Esto no acredita por sí solo la operación Go.
- **Go:** `internal/gallery/transport/http/handler.go` exige bearer/rol para las rutas privadas. El POST multipart usa `Idempotency-Key` y llama `media.Service.UploadSpace` (línea 124); el handler no procesa `replace_photo_id` ni `If-Match`. Aunque `internal/media/service.go` ofrece `UploadSpaceReplacement` y el repositorio PostgreSQL compara revisión durante reserva/finalización, esa ruta de reemplazo no está expuesta por este handler.
- Las rutas de portada, metadatos/visibilidad y retiro llaman `SelectCover`, `UpdateSpace` y `RemoveSpace` sin una revisión esperada. Las firmas correspondientes de `internal/media/service.go` tampoco reciben revisión. Por tanto, el CAS de reemplazo probado a nivel de repositorio F2 no prueba CAS HTTP para estas mutaciones.
- **Contrato:** `planning/openapi.yaml` documenta para el POST multipart únicamente `image` con `additionalProperties: false`; no declara `replace_photo_id` ni `If-Match`. Portada y retiro conservan nombres/DTOs `Synthetic*`, mientras el handler también puede operar sobre medios reales. No se han alineado ni demostrado las respuestas reales de todas esas rutas.
- El contrato normativo de §7 del plan exige CAS en las mutaciones no aditivas y reemplazo multipart protegido. La cobertura mock de cupo 30/31 y ETag del borrador no satisface esos criterios de galería.

## F6 — compuerta de arranque

- `cmd/api/main.go` monta rutas autenticadas bajo perfiles de aplicación, pero el arranque inicia varios workers con potencial de mutación: reconciliación de pagos/contratos, limpieza de media/operaciones, notices y retención/privacidad. `LOCAL_DATASET_DEALS_ISOLATED_CLOCK` condiciona solo algunos; no es un modo global sin workers.
- `local-readonly-probe` es una orden one-shot y no sirve el flujo HTTP browser→BFF→Go. No se identificó un perfil HTTP comprobado que monte las rutas necesarias y omita todos los workers.
- No se inició la API contra el PostgreSQL persistente seleccionado. La autorización de trabajo con datos sintéticos no designa por sí sola un target write-capable para esta integración. Tampoco se crea una base, contenedor o volumen sustituto por inferencia.
