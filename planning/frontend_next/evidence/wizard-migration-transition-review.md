## Hallazgo determinante

Las migraciones `db/migrations/V000081__document_verification_runtime_scope_helpers.sql` a `V000083__document_verification_lock_and_transfer_fix.sql` son inmutables y contienen contratos explícitos que el setup actual no demuestra haber satisfecho. V81 exige roles restringidos `espacigo_migrator_login`, `espacigo_api_login`, `espacigo_schema_owner`, `espacigo_document_verification_fn`, `espacigo_runtime`; schema privado cuyo owner sea el helper; memberships `SET TRUE`, `INHERIT FALSE`, `ADMIN FALSE` exactas; seis grants de columna mínimos al helper con grantor igual al owner de cada tabla; `USAGE` de `public` para helper sin `CREATE`; y `SELECT`/`INSERT` mínimos del ledger para schema-owner, grantor igual al owner del ledger, sin ACL de columna. También prohíbe CREATE de schema para schema-owner y migrador.

Dos aspectos requieren preparar el tránsito, sin implicar una incompatibilidad irresoluble:

1. El bootstrap `db/bootstrap/wizard-improvements/001_roles_extensions.sql` prepara roles, pero no demuestra la creación/propiedad del schema helper ni los grants de columnas/ledger requeridos por V81. Resolver mediante setup versionado y readback; no inferir que falten ni agregar permisos antes del inventario.
2. El ledger aún no existe en este destino. Si el primer comando ordinario crea `public.schema_migrations` bajo `SET ROLE espacigo_schema_owner`, su owner será ese rol; no es necesario ni deseable transferir ownership después. Para evitar que el guard V81 juzgue una propiedad impropia, la alternativa factible a evaluar es preaprovisionar una sola vez el ledger vacío como preparación administrativa del destino, usando el DDL exacto de creación del runner, y establecer directamente ACL mínimas `SELECT`/`INSERT` al schema-owner, con grantor igual al owner (administrador) del ledger. La secuencia normal ejecuta primero `SET ROLE espacigo_schema_owner`; en ese contexto el runner inspecciona la tabla, `readHistory` la consulta y la creación posterior es `CREATE TABLE IF NOT EXISTS`. Luego registra versiones por `INSERT` bajo el mismo rol; el owner no cambia. El código permite esta ruta si `SELECT`/`INSERT` bastan y la creación condicional no falla por privilegios; probarlo en ensayo aislado antes de autorizar la ejecución real. No inventar rol adicional, grant de ownership ni API para manipular ledger; no transferir ownership. Este bootstrap no aplica migraciones como administrador.

`db/repair/f5_pre_v81_role_contract.sql` y los procedimientos de Cloud SQL son evidencia de otros destinos, no instrucciones ejecutables para este ensayo. No copiar sus excepciones, flags, propietarios asumidos ni SQL sin diseñar y revisar una propuesta específica del ensayo.
