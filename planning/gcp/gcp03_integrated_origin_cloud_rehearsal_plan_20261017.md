## Objetivo y evidencia de partida

Ensayar una copia sellada del origen en una instancia Cloud SQL nueva, privada y run-scoped; sanearla, verificarla y retirar únicamente los recursos de ese run. La captura local aprobada del 2026-10-17 tiene SHA-256 de `SEALED.json` `80a4e1e0002cf12f8e750ddaac7ceb796726b57a36405aa2b0b8e7852e928262`. Payload y llave siguen en custodia local. El restore-copy local corregido terminó con checks acotados de catálogo/ACL y agregados; no demuestra compatibilidad Cloud SQL, igualdad completa de datos ni validación final de archivos.

Estado histórico sintético aclarado: en `g03r-1016`, restore y verify de la fixture mínima pasaron sus nueve comprobaciones. El Job SQL de `retire` falló sin reintento; su outcome quedó sin resolver. El posterior teardown Terraform eliminó recursos run-scoped y confirmó las dos instancias baseline `RUNNABLE`. Esto no es restore de snapshot de origen. **No reutilizar `cmd/gcp03restore`, su perfil sintético, su `retire` ni la base `pilot01` para el snapshot.**

El preflight 2026-10-17 encontró dos instancias SQL baseline y cero jobs/servicios Cloud Run en `southamerica-west1`. La lectura SQL vía Data API se negó antes de ejecutar sentencias porque el acceso no está habilitado. El root Foundation fija `data_api_access=DISALLOW_DATA_API`; no se habilita esa API para sortear el bloqueo.

Foundation sí se aplicó bajo liberación específica; el resultado y las verificaciones read-only están en [apply-foundation.json](evidence/gcp03-origin-foundation-20261017/apply-foundation.json). La prueba `scripts/test-gcp03-origin-postgres.sh` usa una instancia PG18/PostGIS local desechable con scripts de init ocultos y únicamente `plpgsql 1.0` inicial; verifica rechazo de baseline inesperado, rollback DDL y de postcondiciones, privilegio `TEMP` efectivo de PUBLIC/observer, objetos generados por extensiones, reporte completo de bootstrap y observación read-only. El superusuario `postgres` local controla solo el fixture y no equivale al rol Cloud SQL `cloudsqlsuperuser`; la integración no toca origen/Cloud SQL ni prueba IAM DB auth. El build OCI local está trazado por el manifiesto privado `.local/testing/gcp03-origin-oci-build-20261017/gcp03origin-manifest.json`, ligado al commit limpio por `source_commit`, digest OCI y SHA-256 del archivo. La capacidad y cuota de las próximas fases exigen una verificación y revisión de plan independientes.
