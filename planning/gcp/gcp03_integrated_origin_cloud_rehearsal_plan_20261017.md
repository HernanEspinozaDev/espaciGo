## Objetivo y evidencia de partida

Ensayar una copia sellada del origen en una instancia Cloud SQL nueva, privada y run-scoped; sanearla, verificarla y retirar únicamente los recursos de ese run. La captura local aprobada del 2026-10-17 tiene SHA-256 de `SEALED.json` `80a4e1e0002cf12f8e750ddaac7ceb796726b57a36405aa2b0b8e7852e928262`. Payload y llave siguen en custodia local. El restore-copy local corregido terminó con checks acotados de catálogo/ACL y agregados; no demuestra compatibilidad Cloud SQL, igualdad completa de datos ni validación final de archivos.

Estado histórico sintético aclarado: en `g03r-1016`, restore y verify de la fixture mínima pasaron sus nueve comprobaciones. El Job SQL de `retire` falló sin reintento; su outcome quedó sin resolver. El posterior teardown Terraform eliminó recursos run-scoped y confirmó las dos instancias baseline `RUNNABLE`. Esto no es restore de snapshot de origen. **No reutilizar `cmd/gcp03restore`, su perfil sintético, su `retire` ni la base `pilot01` para el snapshot.**

El preflight 2026-10-17 encontró dos instancias SQL baseline y cero jobs/servicios Cloud Run en `southamerica-west1`. La lectura SQL vía Data API se negó antes de ejecutar sentencias porque el acceso no está habilitado. El root Foundation fija `data_api_access=DISALLOW_DATA_API`; no se habilita esa API para sortear el bloqueo.

## Fase 0 implementada: Foundation

El root nuevo [gcp03-origin-foundation](../../infra/terraform/environments/testprod/gcp03-origin-foundation/README.md) implementa solo la fase 0 con un state remoto independiente. Run ID `g03o-1017`; state bucket `espacigo-testprod-tfstate-447373903153-gcp`; prefijo `espacigo/testprod/gcp03-origin/g03o-1017`. La revisión read-only previa confirmó que no existe state en ese prefijo, instancia `espacigo-gcp03-origin-g03o-1017-pg`, bucket `espacigo-gcp03-origin-g03o-1017` ni SA `g03o-admin-g03o-1017`.

El plan guardado propone exactamente **7 altas, 0 cambios y 0 eliminaciones**: nueva instancia SQL PostgreSQL 18 N4 2 vCPU/4 GiB, 20 GiB Hyperdisk Balanced, base vacía `espacigo_scratch`, bucket Standard privado, SA admin, metadata de secreto sin versión, acceso al secreto para esa SA y `roles/cloudsql.client` condicionado al nombre de esa instancia. Configura solo IP privada, TLS `ENCRYPTED_ONLY`, connector obligatorio, Data API deshabilitada, IAM DB auth habilitada para fases futuras, y protección de borrado Terraform/API. El bucket usa `force_destroy=false`, soft-delete en cero y sin ciclo automático de vida. Las fuentes VPC/subred son data sources read-only.

El plan no crea jobs, logins SQL, usuarios IAM SQL, versiones/valores de secreto, objetos, reglas de red ni cambios a `espacigo-testprod-pg`, `espacigo-gcp03-pilot01-pg`, VPC/subred, Artifact Registry o state compartido. El state no contiene recursos (`terraform state list` devolvió cero); el objeto `default.tfstate` remoto es metadata de state vacía creada durante `terraform init`. Se usó `terraform plan -lock=false`, sin apply. SHA-256 del binario, SHA del JSON saneado, addresses y acciones se publican en [plan-summary.json](evidence/gcp03-origin-foundation-20261017/plan-summary.json). Los binarios y plan JSON completos permanecen bajo `.local/testing/gcp03-origin-foundation-20261017/` con directorio 0700 y archivos 0600.
