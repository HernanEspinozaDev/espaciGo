No demuestra todavía el replay completo, los grants/ownership de V60, extensiones ni runtime. Ver [resultado y límites del probe](gcp03_role_probe_execution_20261016.md) y [ADR propuesto](adr_gcp03_baseline_migrado_v60_20261016.md).

Al momento de aquellos probes, sus dos conexiones comprobaron que no había tablas de aplicación; el probe creó el rol `espacigo_gadm_bootstrap NOLOGIN`. ## Secuencia aislada propuesta

1. **Bootstrap**, una ejecución como migrador en el scratch existente. El SQL fijo valida la condición de base sin historial/tablas, crea extensiones soportadas si faltan y el rol runtime restringido. `espacigo_gadm_bootstrap` ya existe por el probe: validar atributos exactos y cero membresías y reutilizarlo; no recrear roles ni autogrants. El binario imprime las versiones reales de `btree_gist`, `postgis` y `unaccent` desde `ScratchExtensionVersions`.
2. **Reconcile de membresías**, operación Cloud SQL Admin después de bootstrap y antes de `database_acl`/migración. Preservar solo `cloudsqlsuperuser` en el login migrador, esperar `users.update` y verificar API/roles. Ante resultado incierto, detenerse y conservar el secreto.
3. **Database ACL**, una ejecución como `postgres` con el secreto owner. Revocar TEMP de `PUBLIC` y CREATE de `PUBLIC` en `public`; conceder TEMP en `espacigo_scratch` y CREATE de schema solo al migrador. Verificar positivos/negativos del ejecutor; no usar la credencial owner en otra fase.
4. **Migrate**, una ejecución como migrador tras prechecks de roles/ACL. Ejecutar V1–V61 sin cambiar archivos/checksums ni importar datos/historial. V60 debe reutilizar el GADM preexistente con sus guardas. Detenerse ante guardia, error, historial parcial o conflicto; sin loops ni replays manuales.
5. **Finalize**, una ejecución como migrador: verificar historia/checksums, aplicar `GrantRuntimePermissions` y correr los checks actuales de privilegios runtime. Los checks actuales prueban 16 condiciones positivas/negativas; por sí solos **no prueban** owners de todas las tablas/secuencias/funciones, propietarios de funciones, `search_path` de funciones `SECURITY DEFINER`, grants `EXECUTE` completos, inventario/versión PostgreSQL/PostGIS full-version, ni consultas espaciales representativas. La salida bootstrap actual sí recoge versiones de las tres extensiones, pero no `postgis_full_version()`.
6. **Observabilidad separada, pendiente de revisión/aplicación:** hay una implementación local de una fase fija `observe` en `internal/dbbootstrap/observer.go` y `internal/gcp03scratch/observer.go`. Contiene solo consultas constantes `SELECT`, emite un reporte JSON saneado, y falla si fallan los checks espaciales, ACL o runtime. No se ha compilado en OCI, publicado, agregado a Terraform/Cloud Run ni ejecutado en Cloud SQL. El digest actualmente desplegado `3e5683…` no incluye esta fase. El cambio requiere revisión, publicación de un digest nuevo y un plan separado para el Job fijo antes de cualquier ejecución.

   El alcance del observador implementado incluye servidor e inventario de extensiones (con `postgis_full_version()`), roles/membresías fijos, ACL de base/schema y los 16 checks runtime nombrados, owners de relaciones/secuencias/índices/funciones, `proconfig` y ACL `EXECUTE` por función `SECURITY DEFINER`, además de tres operaciones PostGIS sobre geometrías constantes y el estado/definición del índice GIST sintético esperado.
