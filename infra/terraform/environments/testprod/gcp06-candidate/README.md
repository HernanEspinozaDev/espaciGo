# GCP-06 isolated V64 candidate

This standalone root describes one run-scoped, private PostgreSQL 18 Cloud SQL instance, its empty candidate database, a private object bucket for the sanitized SQL artifact, and one bucket-scoped grant to the instance service identity. It does not reference or manage the connected application SQL instance, the app service, application secrets, or Cloud Run Jobs. It has no remote backend configuration; any later backend choice requires a separately reviewed state prefix.

`enable_candidate=false` by default. Creating resources also requires `confirm_candidate_release=true`. Resource names include a unique run ID, network/project/region are pinned, external IPv4 is disabled, and import storage uses UBLA and enforced public access prevention. The exact SQL object path is `gcp06/<run-id>/data.sql`; its lifecycle rule deletes objects after seven days. Terraform creates an empty database. The artifact is now a portable PostgreSQL 18 plain SQL dump from the sanitized V64 staging database: schema, static seeds, migration ledger and sanitized data, with `--no-owner --no-privileges --no-comments`. It contains no role DDL, ACL statements, or ownership commands; PostgreSQL `COPY` terminators (`\.`) remain. The local harness imported it into a new empty database and verified ledger V1–V64, category seeds, and one catalog candidate. This import was tested with local PostgreSQL 18/PostGIS 3.6.4 as `postgres`; Cloud SQL SQL-import parsing and PostGIS 3.6.0 remain unverified. Objects will be owned by the import actor until a separately reviewed ownership/role plan is applied. Do not connect an application or treat local import success as Cloud compatibility. Deletion protection remains active unless both the destroy toggle and exact run ID confirmation match.

Both temporary object bindings are separately default-off. The import service identity receives only `storage.objects.get`; the named uploader receives only `storage.objects.create`. Each condition matches the single object path and has a required future UTC expiration no more than 48 hours away. No bucket listing, object deletion, or operator-wide project IAM is added. IAM object-name conditions alone do not prevent a new object generation or overwrite. Upload only with `bash scripts/gcp06-upload-candidate-sql.sh`, which uses `--if-generation-match=0` and then verifies exact bucket/object, nonzero generation, size, and the SHA-256 custom metadata before import. The helper must be used for every upload; direct `gcloud storage cp` is outside this runbook. The exact expiration and uploader member must be reviewed before enabling either binding.

The Cloud SQL import API is invoked only in a later, separately reviewed operation. The operator uploading the SQL object and invoking import needs separate authorization; this root does not grant operator IAM or publish data. Before import, verify the target project/instance/database against the approved candidate, the artifact hash and retention, backup/rollback evidence, SQL service identity access, and cost. After import, create the exact NOLOGIN role groups and apply the object ACLs from V60/V64 and the approved runtime contract in a separate, reviewed Cloud SQL step. PostgreSQL 18 automatically grants the CREATEROLE actor ADMIN membership in roles it creates; revoke that membership immediately and verify no membership remains for `espacigo_gadm_bootstrap` before completion. Validate extension versions, ownership, ACLs, public catalog query and runtime access before any application connection. None of those Cloud SQL steps has been executed or validated here. The SQL file rejects databases outside the `espacigo_gcp06_candidate_<run-id>` namespace, but the database-name guard does not replace project/instance allowlisting.

The custom role uses `storage.objects.get`, the documented minimum object permission for a single SQL import; parallel imports may also require `storage.objects.list`. See [Cloud SQL PostgreSQL SQL import requirements](https://cloud.google.com/sql/docs/postgres/import-export/import-export-sql).
