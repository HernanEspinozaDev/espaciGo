# GCP-06 isolated V64 candidate

This standalone root describes one run-scoped, private PostgreSQL 18 Cloud SQL instance, its empty candidate database, a private object bucket for the sanitized SQL artifact, and one bucket-scoped grant to the instance service identity. It does not reference or manage the connected application SQL instance, the app service, application secrets, or Cloud Run Jobs. It has no remote backend configuration; any later backend choice requires a separately reviewed state prefix.

`enable_candidate=false` by default. Creating resources also requires `confirm_candidate_release=true`. The artifact is now a portable PostgreSQL 18 plain SQL dump from the sanitized V64 staging database: schema, static seeds, migration ledger and sanitized data, with `--no-owner --no-privileges --no-comments`. This import was tested with local PostgreSQL 18/PostGIS 3.6.4 as `postgres`; Cloud SQL SQL-import parsing and PostGIS 3.6.0 remain unverified. Objects will be owned by the import actor until a separately reviewed ownership/role plan is applied. Do not connect an application or treat local import success as Cloud compatibility. Deletion protection remains active unless both the destroy toggle and exact run ID confirmation match.

Both temporary object bindings are separately default-off. The import service identity receives only `storage.objects.get`; the named uploader receives only `storage.objects.create`. Each condition matches the single object path and has a required future UTC expiration no more than 48 hours away. No bucket listing, object deletion, or operator-wide project IAM is added. IAM object-name conditions alone do not prevent a new object generation or overwrite. Upload only with `bash scripts/gcp06-upload-candidate-sql.sh`, which uses `--if-generation-match=0` and then verifies exact bucket/object, nonzero generation, size, and the SHA-256 custom metadata before import. The helper must be used for every upload; direct `gcloud storage cp` is outside this runbook. The exact expiration and uploader member must be reviewed before enabling either binding.

The import was reported complete for the run above, but ledger/count verification and application readiness remain unconfirmed.
