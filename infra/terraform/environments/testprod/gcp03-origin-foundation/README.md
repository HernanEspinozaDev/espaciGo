# GCP-03 origin rehearsal foundation

This root implements Foundation and contains two later, independently gated Cloud Run Job definitions. Foundation creates the private zonal PostgreSQL 18 target, empty database, private bucket, admin service account, secret metadata and scoped IAM bindings. `enable_origin_bootstrap_job` and `enable_origin_observer_job` default false; Terraform defines these Jobs but never executes them.

The root is pinned to project `espacigo-testprod` and region `southamerica-west1`; it reads the existing VPC/subnet and never manages them. Each run uses a fresh state prefix, for example `espacigo/testprod/gcp03-origin/g03o-1017`. Foundation defaults off and requires `confirm_origin_rehearsal=true`. Deletion protection is enabled in Terraform and the Cloud SQL API; this root has no protection-lowering input. Teardown must use separate, run-bound plans to lower protection and later remove the exact resources.

The bootstrap Job is one task, parallelism one, zero retries, and uses the admin identity plus one exact numeric Secret Manager version supplied before its plan. Terraform creates no secret value/version, and the Job has no bucket access. Fixed SQL installs `btree_gist`, `fuzzystrmatch`, PostGIS, its Tiger Geocoder and Topology extensions, and `unaccent`, then creates restricted NOLOGIN runtime, GADM and observer group roles. It revokes PostgreSQL's default database `TEMP` privilege from `PUBLIC`. Identity, pristine baseline, extensions, roles, object ownership and effective observer privileges are checked in the same transaction before commit; a failed postcondition rolls back all bootstrap DDL. The report is marked passed only after confirmed commit; a commit acknowledgment failure sets `passed=false` and `transaction_outcome=outcome_uncertain`. Extension-created schemas are allowed only when their relations/functions are extension-owned and the schema contains no application objects. Any uncertain execution requires reconciliation before retry.

The observer Job has a separate service account, Cloud SQL connector with [automatic IAM database authentication](https://docs.cloud.google.com/sql/docs/postgres/iam-authentication), no secret mount and no bucket permissions. It runs fixed queries inside a `READ ONLY` transaction. It checks the exact database identity, PostgreSQL 18, the source-compatible extension names/versions (`btree_gist` 1.8, `fuzzystrmatch` 1.2, `plpgsql` 1.0, PostGIS family 3.6.x, `unaccent` 1.1), restricted roles and empty application baseline. It uses `pg_depend` to identify extension-owned schemas/relations/functions and allows those objects while requiring zero application schemas/relations/functions. The observer report is marked passed only after confirmed completion of its read-only transaction. Creating the observer IAM database user also requires the lowercase SHA-256 of the sanitized successful bootstrap report. Its Cloud SQL IAM name is derived from the observer service-account email so Terraform orders account creation before user registration.

Run `scripts/test-gcp03-origin-postgres.sh` for the opt-in integration. It starts the pinned PostgreSQL 18/PostGIS image with networking disabled and an ephemeral data directory, hides the image's extension-preinstall init script, and starts the target with only built-in `plpgsql 1.0`. The test covers rejection of an unexpected baseline, rollback after a mid-transaction DDL failure, rollback when the `PUBLIC TEMP` postcondition fails, successful bootstrap/report, generated extension objects and the complete read-only observer report. The local `postgres` superuser is fixture control only; it is not equivalent to Cloud SQL's `cloudsqlsuperuser` role and this rehearsal does not test Cloud SQL IAM authentication.

For a future, separately released bootstrap step, `scripts/gcp03_origin_admin_secret.py` is the reviewed credential preparation helper. It requires exact confirmations for the fixed instance/database and existing Secret Manager resource plus `--execute`, refuses any existing secret versions, generates a new password only in process memory, adds one Secret Manager version, then sets only the `postgres` user on the fixed Cloud SQL instance through the Admin API. It never prints or accepts the password as an argument/environment value. It normalizes only the known project ID and project number to the canonical numeric secret resource and sends `X-Goog-User-Project: espacigo-testprod`. A definite pre-acceptance SQL rejection disables the newly created version; once Cloud SQL returns an operation ID, any polling error or timeout preserves that exact version as uncertain and stops without retry or rotation. This helper has not been run; its existence does not authorize secret creation or password change.

For image traceability, `scripts/build-gcp03-origin-oci.sh PRIVATE_OUTPUT_DIRECTORY` refuses dirty source and overwrites, builds the pinned `linux/amd64` OCI image from the commit, and writes the source SHA, OCI manifest digest and archive SHA-256 into a 0600 manifest beneath a 0700 directory; the archive is also mode 0600. This builds locally and does not publish. Any later publication is a separate release to the existing Artifact Registry repository `southamerica-west1-docker.pkg.dev/espacigo-testprod/gcp03-scratch-pilot01/gcp03origin` using the exact reviewed digest.
